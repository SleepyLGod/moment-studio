MOMENT / ARCHITECTURE REVIEW / 2026.11.03

一个应用，边界清楚。

图库管理你的照片，任务模块管理执行，模型接口处理供应商变化。

讨论稿 · 已有 Sites / D1 / R2 保留 · 新增设计尚未实现 · 不修改当前网站

图里的 Library、Jobs、Runner、Adapter 是同一个应用里的代码模块。保留一个仓库与两种存储，模型调用不会直接改相册。

已有：登录 / 私人图库 / D1 / R2新增：任务与 NVIDIA 接入待验证：可靠后台唤醒

怎么整理

月份是时间视图；相册由你创建；AI 标签直接应用，短期分组单独出现。AI 不覆盖人工修改，不增加逐项确认。

怎么省空间

一份原图、一张共用缩略图。色调保存参数；相册保存引用；AI 只长期保留你保存的成果。

一个必须先解决的事实：当前项目还没验证可靠后台触发入口。D1 中有 job 不代表它会自己执行；关闭网页后继续完成，需要真实云端验证。

接口与模块的对应关系

外部接口：前端说业务，不说 NVIDIA 协议

接口表达什么边界
/api/uploads → /body → /complete上传文件沿用；原图不可覆盖
GET /api/photos?month=&tag=&cursor=按月 / 标签浏览扩展；服务端分页
PUT /api/photos/:id
PUT /api/albums/:id		人工标签、相册成员与顺序校验归属和 revision
POST /api/jobs识图 / 分组 / 风格生成新增；202 + jobIds
GET /api/jobs?ids=...读取进度和结果不负责启动执行
POST /api/ai/models/refresh刷新候选，优先上次成功模型新增；候选 ≠ 已实测可用
GET /api/groups
POST /api/creations		临时分组 / 正式保存成果新增；不复制原图
GET /api/files/:id看图与下载鉴权后读取；缩略图共用

内部接口：围绕能力，不围绕模型名字

ModelCatalog.refresh()        → 候选与能力
VisionModel.analyze(input)    → 已校验标签 / 描述
ImageEditor.edit(input)       → 图像结果（接通时再实现）
PendingResults.check(receipt) → 可查询任务的结果
TaskRunner.runDue(limit)      → 领取并推进到期任务

前端不传 API key；后台任务固定输入和模型。已有模型的 202 / requestId 是否可恢复，需要验证对应端点，不能套用别的服务的查询地址。

上传流程沿用现有接口。AI 生成任务额外先把图像结果写入 R2，再提交 D1 引用；两种存储之间没有跨库原子事务。

从实际变化出发，而不是先画很多层

会变化的东西隔离在哪里保持稳定的东西
模型上下线、额度、接口格式NVIDIA Adapter标签 / 图像编辑输入输出
后台在哪里执行TaskRunner.runDue任务状态、图库规则

将来 Go / Docker / 其他云HTTP 契约与数据迁移前端业务流程；不承诺代码自动移植

刷新与选模

页面刷新 → 更新一次候选 → 能力匹配 → 优先上次实际成功模型 → 一批任务固定选择。只取目录，不逐个发图探测；429 延后原任务，认证失败明确停止，不随机换模型。

少而必要的可靠性

D1 存任务事实；条件领取防止并发；执行 token 防止旧进程覆盖结果；标签与成功状态一起提交。超时无法查询时显示结果未知，不把网络重试等同于生成重做。

少而必要的数据

沿用 photos / files / albums / styles，只新增 jobs。月份不建实体相册；临时分组先用 group 任务结果。查询字段加索引，有限配方与标签保存为有界 JSON。

本轮不引入

微服务、内部 HTTP、Redis、向量数据库、事件总线、Agent 框架、通用工作流引擎、多供应商兜底链、通用 Repository 基类。

实施前的验证顺序

① 关闭页面后的真实后台执行　② NVIDIA 自有图片输入、目录与回执　③ 原图保留、人工标签保护、任务与结果一致提交。

尚未解决：Sites 的可靠后台触发方式，以及 NVIDIA 目录对当前账户权限的表达。它们是明确的验证任务，不能用假成功或临时浏览器循环掩盖。
